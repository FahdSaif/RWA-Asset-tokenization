# Cost measurements for the ARCA reference prototype

Generated by `scripts/benchmark_costs.py`. All times are wall-clock milliseconds, mean ± standard deviation over `n` repetitions, single process, single core.

*Environment:* Intel(R) Xeon(R) Processor @ 2.10GHz; Python 3.12.3; Linux-6.18.44-fc-v153-x86_64-with-glibc2.39; cryptography 46.0.6, tinyec 0.4.0, web3 8.0.0, eth-tester 0.14.0b1, scikit-learn 1.8.0; run date 2026-10-26.

**Scope.** These are cost figures for the prototype on one machine. They are not throughput claims, and the zero-knowledge stage uses the Sigma-protocol construction described in Sec. VII-F, not a succinct proof system.

## A. Per-transaction validation latency (Python Runtime Enforcement Layer)

Transaction with 3 CRRs and 4 rules (amount, eligibility, risk, anomaly), no zero-knowledge rule (n = 300):

| Stage | ms |
|---|---|
| CRR verification (3 signatures) | 0.41 ± 0.06 |
| Audit-log append (hash chaining) | 0.02 ± 0.00 |
| Other (rule lookup and evaluation, registry checks) | 0.05 |
| **Total** | **0.48 ± 0.07** |

Same transaction with the zero-knowledge jurisdiction rule and issuer-credential binding added, by allow-list size *n*:

| Allow-list size | Total validate() | Jurisdiction binding (credential + ZK verify) | CRR verification | Audit append | Holder-side proof generation | Reps |
|---|---|---|---|---|---|---|
| 8 | 487.08 ± 28.95 | 486.36 ± 28.96 | 0.52 ± 0.06 | 0.06 ± 0.00 | 431.83 ± 21.98 | 20 |
| 16 | 967.53 ± 47.84 | 966.82 ± 47.85 | 0.51 ± 0.02 | 0.06 ± 0.00 | 874.91 ± 4.78 | 20 |

The zero-knowledge membership proof is the only size-dependent stage and grows roughly linearly with the allow-list size, as expected for this construction. Everything else is size-independent.

## B. Governance operations (computational cost only)

Rule update with a 2-of-3 quorum (n = 50):

| Step | ms |
|---|---|
| Propose | 0.02 ± 0.00 |
| Two votes (signing) | 0.12 ± 0.02 |
| Finalize (verify votes, check quorum) | 0.30 ± 0.02 |
| Apply (registry re-verifies quorum, updates rules) | 0.28 ± 0.01 |
| **Total** | **0.72 ± 0.03** |

Agent registration (propose, three votes, finalize, apply): 1.01 ± 0.03 ms.

Human or organisational voting latency is a deployment parameter and is not measured here. It determines the Threat Class II exposure window (Sec. VI-B, VII-E).

Compliance gate overhead (new recipient): 15,118 gas (29.2%).

Compliance gate overhead (existing recipient): 15,118 gas (43.7%).

The baseline `PlainToken` is identical to `ComplianceToken` except for the two registry checks, so the difference isolates the cost of the gate. These are the prototype's own contracts; no measurement of ERC-3643 itself is made here.
